                What it does

                When it starts

                When one of these sites shows its sign-in page, the extension signs you back in through Google: . For Slack, that's the workspace page it sends you to when it signs you out (app.slack.com/workspace-signin), unless it's asking about a workspace other than . It doesn't start until you're looking at the tab, so nothing sits half signed in going stale while you're away. To sign in to a site now, open it from the toolbar popup's site list.

                What a sign-in run does

                1. The site's own sign-in steps: clicks what you clicked when you recorded it (its Google button, say), filling in your email where you typed it. Each step happens once, on the page it was recorded on. For Slack, the workspace page first goes straight to , so there's nothing to type. If Slack's page has been open more than minutes, the extension reloads it first so Slack's security token is fresh.
                2. Google's account chooser: clicks , never "Use another account". It does this only once the page shows the sign-in is for the site the run started on.
                3. Google password (only when Google has signed you out too): focuses the box and waits for you. With the password option above switched on, it clicks Next once your password manager fills the box in.
                4. Google's Continue and Allow pages: clicks them.
                5. The site's own code page (Slack's, and any site whose recording stopped at a code or password box): focuses the box and hands over to you. The run ends here. Sites without one are done once their normal pages have loaded.
                6. Google itself: when you land on Google's own sign-in, for example Gmail asking you to sign in again, it picks your account and handles the password the same way. It never clicks Continue or Allow there. Every other site's run goes through these Google steps anyway.
                7. After you enter Slack's code: Slack tries to open the desktop app. With "Skip the Open Slack? prompt" switched on, the tab goes to Slack in the browser instead: your chosen page if you set one, otherwise the workspace's default view.

                How it keeps itself safe

                • One tab, one step at a time. A run belongs to the tab it started in, and only one runs at once; a sign-in page in another tab waits its turn. Each step has to follow within minutes of the last, or minutes while it waits for your password. If the next page never arrives, or a button it needs doesn't appear within 10 seconds, the run stops and a notification names the step.
                • Only the run's own Google sign-in. On Google's pages it acts only during a run it started from one of these sites, and only once Google's address names that site (or the page says it's continuing to it). Signing in to Gmail or anything else is left alone.
                • The loop guard. If something goes wrong and a site keeps sending the tab back to its sign-in page, each return would start a new run. To stop that hammering Google's sign-in, the extension allows at most automatic runs per site in minutes. After that:
                  • It pauses automatic sign-in for that site and shows a red and a notification.
                  • It resumes by itself once the oldest of those runs is minutes old. A sign-in page that's still open then carries on by itself, as soon as you're looking at it.
                  • A run that signs you in (or reaches MFA) resets that site's count, because that shows nothing is stuck.
                  • Reloading the extension clears the pause.
                • No secrets. It never reads, stores or fills in a password or MFA code. To decide when to click Next on the password page, it looks only at how much is in the box and at the input events. The browser marks your real keystrokes as trusted, and a password manager's simulated ones aren't. A fill in one go, or keystrokes at machine speed, also count as a password manager. So a password you type is left for you to submit, and typing over a fill hands the box back to you. It clicks Next only once the box has stopped changing, and at most once per page, so a wrong password can't be resubmitted in a loop.

                The toolbar badge

                Signing in.
                Waiting for your Google password.
                A site's MFA code box is ready for you. Clears after minutes.
                A run stopped, or the loop guard paused. The popup says which.
                Signed in to Slack: the Slack client loaded and stayed loaded.
                Signed out of Slack: a Slack sign-in page for this workspace is open.

                When no run is going on, the badge shows ✓ or ✗ for Slack. That's whatever the last Slack page you had open showed. If you close every Slack tab, it keeps the last status, because it doesn't check with Slack in the background.

                The popup also has an on/off switch, a dry run mode that outlines in red what it would click instead of clicking, and a log of the last runs.
